## (B) WHAT THE SCAN/ANALYSIS ENGINE ACTUALLY OUTPUTS

### REAL IMPLEMENTATION:
The camera screen (`camera.tsx`) integrates with the **Google Gemini Vision API** for actual AI analysis.

**API Details (`scanStore.ts`):**
- **Model:** `gemini-3.6-flash`
- **API Key:** Hardcoded in source (exposed client-side - security concern)
- **Endpoint:** `generativelanguage.googleapis.com/v1beta`

**Analysis Output Schema:**
```typescript
interface SkinAnalysisResult {
  overall_score: number;        // 0-100 overall skin health
  skin_type: string;            // "Oily" | "Dry" | "Normal" | "Combination"
  concerns: SkinConcern[];      // Array of 8 required items:
    // Acne, Dark Circles, Eye Bags, Blackheads, Dark Spots, Wrinkles, Pores, Redness
    // Each with: name, severity ("None"|"Mild"|"Moderate"|"Severe"), detected (boolean)
  recommendations: string[];    // 3 actionable tips
  summary: string;               // 2-3 sentence overall assessment
}
```

**Actual Process:**
1. User takes photo → Saved to `scanStore.imageUri`
2. `runAnalysis()` called → Converts image to base64
3. POST to Gemini API with structured prompt
4. Parses JSON response
5. Results stored in `scanStore.scanResult`
6. Navigation to `scan/[id].tsx` with ID "1" (mock)

**Limitations:**
- Only works when camera is used (not from gallery in current implementation)
- Hardcoded to use scan ID "1" regardless of actual scan
- No persistent storage of scan history to backend
